# **One line**

A memory-safe for cards: snap, auto-transcribe, tag by person or event, and resurface moments when they matter.

# **Problem and goal**

Physical cards carry meaning but create clutter and fragility. People want the sentiment without the storage burden. The goal is to provide a fast, low-friction capture and recall system that preserves the message, the giver, and the moment.

# **Target users**

- New parents, newlyweds, recent grads
- People decluttering after moves or life events
- Families preserving messages from aging relatives

# **Jobs to be done**

- When I receive a card, I want to preserve its meaning without keeping the paper, so I can toss it guilt-free.
- When I miss someone, I want to find what they wrote, so I can feel connected.
- When I organize keepsakes, I want minimal effort, so nothing piles up.

# **Core experience pillars**

1. Capture
2. Organize
3. Recall
4. Share
5. Memorialize (roadmap): memory reels, resurfacing rituals, memorial mode

# **Principles**

- Low friction: two taps after scan
- Human centric: images and text live together
- Trust first: default private, clear sharing, easy export
- Useful AI: suggestions, not chores

# **V0 scope (small, lovable, and testable)**

**Capture**

- P0: Guided scan for front and inside pages
- P0: Auto edge detection, de-skew, glare reduction
- P1: OCR + handwriting transcription with confidence score
- P1: Speaker detection: parse sign-offs like “Love, Mom” and suggest a contact

**Organize**

- P0: One-tap tags: Person, Event, Year
- P1: Auto-suggest event from text
- P0: Albums: People and Events

**Recall**

- P1: Full-text search across OCR
- P0: Filters: Person, Event, Year
- P1: Timeline view

**Share**

- P0: Invite friends to app
- P1: Private link for a single card or album
- P1: Optional PDF export
- P2: Post to socials (organic growth/virality) with custom designs

**Non-goals for V0**

- P2: Reminders and resurfacing rituals
- Notifications (e.g., reminders for new users who didn’t activate, reminders after holidays)
- Collaborative editing beyond basic share links
- Public feeds
- Printed books

# **User stories and acceptance criteria**

1. As a user, I can scan a card front and inside and see a cleaned image.
    - Accept if the scan flow completes in 3 steps or fewer and shows a preview with clear edges.
2. As a user, I can review an auto transcription with low-confidence words highlighted.
    - Accept if words below a confidence threshold are visually marked and can be tapped to edit.
3. As a user, I can assign a giver and event in one tap from suggestions.
    - Accept if the first suggestion is correct 70 percent of the time in tests.
4. As a user, I can search for a phrase or a person and find a matching card within 1 second for a 500 card library.
    - Accept if p95 search latency is under 1000 ms with 500 cards and 1 GB of media.
5. As a user, I can create a share link for a single card and revoke it later.
    - Accept if a link can be created and revoked in under 10 seconds and revocation blocks access.

# **Core flows**

1. New card capture
    1. Tap New Card
    2. Scan front, then inside
    3. AI generates title, tags, and contents/a quote
    4. User confirms or edits and saves
2. Find a memory
    1. Open “Your Cards”
    2. Filter by Person or Event (can also search by term)
    3. Tap result to view images and text
3. Share a card
    1. From card detail, Create link
    2. Copy link to share
    3. Revoke in Share settings (accessible when viewing individual cards and full albums)

# **Minimal flow**

1. Tap “New card” → camera opens → scan front → scan inside
2. AI suggests title “From Aunt Sara • Leila’s 1st Birthday”
3. You confirm tags. Done.
4. Card appears in timeline and in “Aunt Sara” album.

- Default private. No public discovery.
- Images and text encrypted at rest. TLS in transit.

## **Lightweight validation you can run immediately**

- **Paper prototype**: 5 screen wireflow. Time the capture to “Done.”
- **Concierge test**: have 5 users text you photos of 10 cards; you do manual tag + OCR behind the scenes. Measure effort and delight.
- **Message recall test**: ask users one week later to find “the last card from Dad.” Watch time to retrieval.

# **Risks and mitigations**

- Handwriting OCR errors: keep image and text side by side, highlight low confidence, tap to correct
- User friction: reduce fields to optional, smart defaults
- Privacy concerns: simple privacy settings and clear share controls
- Performance on large libraries: incremental indexing, local search with server sync

# **OCR Benchmark Plan**

## **Purpose**

Measure real-world OCR quality for printed and cursive handwriting, then define thresholds for acceptable UX with confidence highlighting and correction.

## **Dataset**

- 50 cards total (expand later):
    - 20 printed fonts (varied weights, colors)
    - 20 cursive/handwriting styles
    - 10 mixed or decorative (foil, textured paper)
- Conditions: each scanned under 3 lighting scenarios (good, warm indoor, challenging glare) and 2 angles (flat, slight skew)
- Language: English for V0; include 5 with common non-English words/names

## **Ground truth creation**

- Human transcription with double-blind review
- Mark line breaks and punctuation faithfully
- Annotate entities: giver, relationship, event, date, quote

## **Providers to test (swappable)**

- Provider A: General OCR
- Provider B: Handwriting-focused
- Provider C: Platform-native (e.g., on-device)

## **Metrics**

- Text accuracy: Character Error Rate (CER) and Word Error Rate (WER)
- Named entity accuracy: precision/recall for giver, event, date
- Layout fidelity: paragraph/line breaks F1 (simple heuristic)
- Confidence calibration: correlation between provider confidence and actual token accuracy (AUC)
- Throughput: avg processing time per image pair (front+inside)

## **Pass thresholds (V0)**

- CER ≤ 8% on printed, ≤ 18% on cursive
- Giver extraction F1 ≥ 0.80 on printed, ≥ 0.65 on cursive
- Event classification accuracy ≥ 0.90 printed, ≥ 0.75 cursive
- Mean latency ≤ 3.5s per card (server-side), p95 ≤ 7s

## **Scoring rubric for UX readiness**

- Green: meets all thresholds → auto-accept suggestions
- Yellow: misses 1 threshold slightly → show more highlights and prompt quick review
- Red: misses 2+ thresholds → skip auto-fill, require minimal manual fields

## **Test procedure**

1. Capture each card with the app’s scan flow
2. Run OCR through each provider
3. Normalize outputs → compare to ground truth
4. Compute metrics and generate per-card report
5. Aggregate provider comparison leaderboard

## **Reporting artifacts**

- Per-card JSON summary
- Provider leaderboard table
- Confusion examples gallery (before/after, low-confidence tokens)

## **Operationalizing in product**

- Dynamic provider routing by card type/lighting (fast path vs quality path)
- Store both raw OCR and humanized text
- Use token-level confidence to drive inline highlight UX
